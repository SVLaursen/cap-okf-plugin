## Open issues and risks carried into Phase 1

- **No remote, no CI.** Everything was checked locally only. Once the repository is pushed:
  - CI must run green (before G2);
  - the required status checks in HANDOVER.md must use the real job names (`Test (Node 22,
    cds 10)` and `Test (Node 24, cds 10)`, not `Test`);
  - branch protection with one required approval blocks merging PRs that Claude Code opens
    through your own GitHub login; decide on admin bypass or a separate account.
- **`@gavdi/cap-mcp` work:** the handoff in `docs/upstream/gavdi-cap-mcp/` goes to that project's
  developer. Task 4.6 is blocked until a release emits `mcp:resources`.
- **ADR-0004 wording:** its context table says `call_action`; the `@cap-js/mcp` tool is named
  `call`. ADR-0004 is Accepted, so the project hook blocks agents from editing it; it's a
  one-word edit for the maintainer.
- **`cds compile … --to okf` from the repo root needs `CDS_PLUGINS`** (ADR-0005). The command in
  `CLAUDE.md` (line 33) and `.github/workflows/ci.yml` (line 32) needs changing in task 2.8. Both
  files are edited by a human.
- **Node.js floor:** `CLAUDE.md` says Node.js ≥ 22; `package.json` now says ≥ 22.12 (needed by
  cds 10). The cds 9 support was dropped by the maintainer's decision on 2026-11-13.
- **Main history:** task branches were fast-forwarded with their individual commits rather than
  squash-merged, because the guard hook blocks commits on `main`. This keeps the test-first order
  visible.
- **Small content notes from the spec-checker (not failures):**
  - `demo/okf/guides/ordering.md` line 25 names `AdminService` outside the auth markers. That
    hints at who has access. Consider rewording it or moving it into the section.
  - `demo/okf/index.md` line 8 adds "(draft)" to the returns description (§8 SHOULD reuse the
    concept's description).
- **For the Phase 1 validator (1.3):** the `yaml` parser returns `generated.at` and `stale_after`
  as strings. The validator must check the ISO 8601 format itself. The copied sample bundles
  have no frontmatter in any `index.md` and contain a `.py` file; see `test/fixtures/okf-spec/SOURCE.md`.
- **Still to prove in later tasks** (listed in the ADRs):
  - real `jwt`/`ias`/`xsuaa` auth for the static route (4.3);
  - the `OkfService` READ handler in production, and its query subset (4.5);
  - `@protocol: 'none'` under `@gavdi/cap-mcp` (4.5);
  - the package model path `cap-okf/srv/okf-service` (4.5);
  - the `cds build` order that ADR-0005 (e) and ADR-0007 rely on (2.9, 4.5).
