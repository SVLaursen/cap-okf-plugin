## Open issues and risks carried into Phase 2

**Need a maintainer decision**

1. **CI waiver, renewed** (maintainer, 2026-11-16) until a remote exists. CI must be green at the
   first gate after the remote is set up. Until CI runs, nothing has been tested on Node 22 or 24
   (CI's matrix), on Linux, or on Windows.
2. **Licence review of `@sap/xssec` 4.16.0** (open since Phase 0). It is in `package-lock.json` as a
   dev and peer dependency under the "SAP DEVELOPER LICENSE AGREEMENT". It isn't shipped, but the
   REUSE job and a licence policy may flag it.

**Maintainer-owned files that still describe the JavaScript layout** (ADR-0009 consequences; these
files are human-maintained)

3. `CLAUDE.md` still says `lib/core/` is pure (it is `src/core/` now), and "Node.js ≥ 22" (the
   package needs ≥ 22.12). Its commands table predates TypeScript.
4. `.claude/hooks/lint-file.mjs` lints only `.js`, `.cjs` and `.mjs` files, so edits to `.ts` files
   are not linted by the hook (`npm run check` still lints them).
5. `.claude/agents/reviewer.md` and `.claude/commands/gate-check.md` name `lib/core`.

**Carried into Phase 2 and later tasks**

6. **Stale files in `gen/okf`.** `FileBundleSink` writes and replaces files but never deletes any.
   The build task (2.9) must clear old files, or a removed entity stays in the bundle.
7. **The demo bundle's links into `model/`.** `demo/okf` has 4 W4 warnings for links into the
   not-yet-generated `model/`. A test allows exactly these and is meant to fail once Phase 2 merges
   `model/` in; then it should expect no findings at all.
8. **Root `index.md` merge.** `generateIndex` can write the root index with `okf_version`; choosing
   between it and a curated `okf/index.md` (ADR-0007) is task 2.7's job.
9. **Paths that differ only in case.** A curated `Index.md` counts as a concept (the spec's reserved
   names are lowercase), but on macOS and Windows it clashes with a generated `index.md`. The sinks
   refuse case clashes within one bundle; task 3.1 should report them for curated files.
10. **Not yet checked by the validator** (out of scope for Phase 1): frontmatter path fields (§6.2)
    as links, and the timestamps inside `sources` entries (`last_modified`, `usage_window`).
11. **Interoperability of unquoted timestamps.** cap-okf writes `at: 2026-07-10T23:14:11+00:00`
    without quotes, as the `acme_retail` samples do; in 44 sample files the quotes were there before.
    YAML 1.2 readers (ours) read it as text; YAML 1.1 readers such as PyYAML read it as a date. The
    spec allows both. Options: always quote timestamps when writing, or note it in the README
    (Phase 3).
12. **Windows.** The bundle sinks guard against names Windows can't store, but nothing has run on
    Windows. The symbolic-link tests need extra privileges there; keep that in mind before adding
    a Windows CI job.
13. **PR size.** Tasks 1.3–1.6 went over CLAUDE.md's ~400-line guideline, mostly through review
    fixes and their tests (1.3 about 1,150 lines). The maintainer accepted 1.3 as it was. Phase 2's
    mapper tasks are smaller and should fit.
14. **From G1, still open:** ADR-0006 Contract A is agreed, but task 4.6 stays blocked until a
    `@gavdi/cap-mcp` release emits `mcp:resources`. ADR-0008 (Fiori source of truth) must be
    accepted before Phase 5.

15. **The R3 rules don't match the spec's strength exactly** (spec-checker):
    - stricter for `log.md`: dates not newest first, and a date repeated, are errors, but §9 only
      makes the `YYYY-MM-DD` form a MUST. Consider making the order rules warnings;
    - looser for `index.md`: an index with entries but no section heading passes, though §8 says
      entries are grouped under headings. Our generated indexes always have headings.
16. **Generated indexes leave out folders without Markdown.** In `acme_retail`, `attesters/` holds
    only `sql_equality.py`, so a generated root index doesn't list it; the official index does.
    Listing is a MAY in §8. Decide in task 2.7 whether such folders should be listed.
17. **Path-valued fields in a sample resolve from the bundle root.** In
    `acme_retail/computations/revenue-ytd.md` and 4 other files, values such as
    `executor.resource: skills/run-on-bq.md` (12 in all) only resolve from the bundle root, while
    §6.2 reads them relative to the file. Keep this in mind if a later task checks path fields
    (item 10).
