## Open issues and risks carried into Phase 3

**Need a maintainer decision**

1. **Timing tests and the coverage provider** (resolved during the gate). Wall-clock tests carry
   "(timing)" in their name, are skipped when Jest's default (istanbul) coverage instruments code,
   and run through `npm run test:timing`, which CI runs after the coverage step. If
   `jest.config.js` ever switches to `coverageProvider: "v8"`, the skip needs another signal (an
   opt-in variable such as `OKF_TIMING=1` was the reviewer's alternative).
2. **CI waiver**, renewed 2026-11-16 until a remote exists. Nothing has run on Node 22 or 24, on
   Linux or on Windows. `.gitattributes` (2.10) now keeps fixtures and goldens byte-exact on a
   Windows checkout.
3. **ADR-0010 is Proposed.** Phase 4 can't start until it is accepted (with the `bundleHash`
   placement and the `(tenant, locale)` scope, or changes). Then ADR-0006 is marked Superseded and
   the amendment text at the end of ADR-0010 is added to ADR-0004.
4. **Licence review of `@sap/xssec`** (open since Phase 0), unchanged.

**Maintainer-owned files** (human-maintained)

5. `CLAUDE.md`: the compile command in its table needs `npm run cds:okf -- compile
   test/fixtures/bookshop --to okf` (CAP doesn't load a project's own `cds-plugin.js`, ADR-0005);
   and G2's items 3–5 (`lib/core` naming, Node ≥ 22.12, `.ts` linting in the hook) are still open.

**Carried into Phase 3 and later tasks**

6. **Descriptions and doc comments can disagree** (spec-checker). The one-line description is
   `@description` (often an i18n text) before the doc comment's first sentence, so e.g. `Books`
   says "Books that the shop sells, with stock and authors" in the frontmatter and "A book that
   the shop can sell." in the body. Works as decided in 2.1/2.5; README (3.5) should explain it.
7. **SHOULD-level style points** (spec-checker): the element table is under `## Elements`, not the
   conventional `# Schema` heading (§4.2); `resource` uses a `cds:` scheme consumers can't follow
   (§6.2 lists URLs and paths); descriptions from i18n may lack a closing period.
8. **Known follow-ups from Phase 2:** Markdown inside i18n texts isn't escaped; CAP prefers
   `@Common.Label` over `@title`; write protection of auto-exposed entities isn't shown;
   `cds compile -o` never deletes stale files (documented; `cds build` does); `cds compile --help`
   doesn't list `okf` (README).
9. **Golden files follow `@sap/cds`.** `model/User.md` and the managed fields come from
   `@sap/cds/common` and its texts; CI installs the latest `@sap/cds@10`, so a reworded text in a
   cds release changes the golden bundle without a change here.
10. **Build task branch coverage** is 82% in `src/build` (the in-process test covers validation
    errors; feature toggles have no test). `this.context.tasks` is undocumented CAP API, guarded
    only by the build tests (ADR-0007).
11. **From G2, still open:** curated `Index.md` case clashes (3.1); validator gaps for path fields
    and `sources` timestamps; unquoted timestamps and YAML 1.1 readers; the R3 strength
    differences for `log.md`; root `index.md` merge with a curated `okf/index.md` (3.1).
12. **PR size.** 2.9 was about 600 lines with its review fixes (about 300 of them tests).
